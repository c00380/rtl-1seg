# rtl-1seg
<img width="1899" height="894" alt="image" src="https://github.com/user-attachments/assets/592bb54b-b980-488a-a4ba-b41558a8ff60" />

RTL-SDRでワンセグ放送をブラウザで受信できます。もともと`Gnu Radio`と`vlc`を使って受信していましたが、環境構築がものすごく面倒だったり映像がすぐに止まってしまうなどの問題がありました。ブラウザバージョンに移行したことで、インターネットブラウザがあれば受信できるようになりました。  
本プロジェクトは[Pages](https://c00380.github.io/rtl-1seg/)にも公開しています。

## 動作環境
- Chromiumベースのブラウザ
  - **推奨ブラウザはChromeです。** 他のブラウザでは、一部の機能が正常に動作しない場合があります。
- RTL2832UとR820T／R820T2／R828D系チューナーを搭載したRTL-SDR
  - RTL-SDR V4で動作を確認しています。
- Node.js/npm（ビルド時）

RTL-SDRはブラウザの`WebUSB`機能を用いて制御します。本アプリはファイルの操作に一時的にストレージを使用します。扱うファイルのサイズによっては空き容量が足りなくなる可能性があります。

## ビルド
```sh
# ソースコードのクローン
git clone https://github.com/c00380/rtl-1seg.git
cd rtl-1seg

# Node.jsでビルド
npm run setup

# サーバー起動・http://localhost:8000
npm start
```
サーバーは`http://localhost:8000`でホストします。ルートの`start.bat`でも起動できます。  

## 基本的な使い方
<img width="493" height="466" alt="image" src="https://github.com/user-attachments/assets/a19bd664-65d0-475f-9940-5727ff7440c1" />

1. サーバーにアクセスする
2. RTL-SDRを接続する
3. `受信を開始`ボタンを押す
4. 接続しているUSBデバイスを選択する
5. 周波数とゲインを設定する

ゲインの初期設定は`32.8 dB`です。  
USBデバイス一覧にRTL-SDRが出てこない場合、USBのドライバーが合っていない可能性があります。Windowsなら`WinUSB`を推奨しています。  

## 各種機能
### 映像のデコード
受信した映像をリアルタイムでデコードします。  
映像が途中で途切れる場合、処理が追いついていない可能性があります。

### 放送局・番組情報の取得
放送局名と番組タイトル・概要、次の番組を表示します。ワンセグでは基本的に現在の番組と次の番組の情報が送信されます。放送局が対応している場合、**5,10番組先**までの情報も取得できます。（私の環境で受信できる放送はほとんどが対応していました）   
番組概要では、番組名と簡単な概要・番組ジャンル・放送時刻が取得できた番組数表示されます。  


理論上すべての放送局の番組情報を取得して番組表を作成することは可能ですが、RTL-SDRの制約によりできません。   

### 現在時刻の表示
ワンセグでは現在時刻を放送に含めておりその情報をデコードして表示します。**パソコン内の時刻を表示しているものではありません**。処理の速度によって更新が遅れるときがあります。

### 字幕、二重音声等
設定で字幕や二重音声の設定を切り替えられます。二重音声は対応していない番組ではグレーアウトします。

### データ放送の受信
ワンセグ専用のデータ放送を受信します。私の受信環境では`ABCテレビ携帯`以外はほとんどサービスが終了しています。

### 受信情報等の表示
<img width="1852" height="866" alt="image" src="https://github.com/user-attachments/assets/3bd7d9d7-7bbc-45db-94e2-2b444f02d62f" />

`受信の詳細`では放送からこのアプリが解析できるほぼすべての情報を表示します。一部ワンセグサービス以外の情報も表示されます。受信パネルではスペクトラム表示やコンスタレーション表示などの信号のデバッグ画面が表示されます。

### 録画
放送中の番組を録画します。予約録画などの機能はありません。  
設定で`.mp4`か`.ts`かを選べます。.`ts`で保存すると字幕データなどのすべての情報をそのまま保存できますが**`.mp4`で保存すると映像と音声のみ保存されます**。  
番組にコピー禁止フラグがある場合録画機能は使えなくなりますが、地上波でそんな番組は滅多に放送されないはずです。

### チャンネルスキャン
`チャンネルをスキャンして自動登録`ボタンでチャンネルスキャンができます。放送を取得できた場合はその下にチャンネル番号でボタンが追加されます。この番号はリモコンの番号と同じように操作できます。なお同じリモコン番号の放送が二つ取得できた場合、入力レベルが強い放送が優先されます。

### ファイル入力
I/Qファイルの入力に対応しています。`8-bit signed`,`16-bit signed`,`32-bit float`の入力形式に対応しています。  
注意として、**形式とサンプルレートは入力のファイルに合わせる**必要があります。なおプログラム上の都合によりサンプルレートには一部使用できない数値があります。

### 送信用ファイルの生成
<img width="609" height="648" alt="image" src="https://github.com/user-attachments/assets/9c120ff5-99ff-4e0b-bf70-4a3a58563600" />

送信用のI/Qファイルの生成ができます。入力は`.mp4`などの動画ファイルか`.ts`などの放送用ファイルの入力に対応しています。ファイル入力機能の時と同じ`8-bit signed`,`16-bit signed`,`32-bit float`の出力形式に対応しています。  
追加情報として、`番組名`,`放送局名`,`説明`を入力できます。パケットサイズの制限により文字数には限度があります。

> [!WARNING]
> ***電波法第4条に基づき、必要な免許や資格、許可等を得ずに電波を送信することは禁止されています。利用者は自身の責任と管轄法令の範囲内で使用してください。***
>
> 
> I/Qファイルは波形情報をそのまま保存する**非圧縮形式**です。短時間の動画のエンコードでも数GBに達するおそれがあります。

## 補足事項
### 放送局ロゴについて
通常ワンセグでは放送局ロゴを取得できません。そのため事前に主要放送局ロゴを保存しておき、受信時に対応する放送局ロゴを表示するようにしています。対応するロゴがない場合はワンセグから取得できた簡易文字ロゴを表示します。  
ロゴのリストは[KonomiTV](https://github.com/tsukumijima/KonomiTV#%E5%B1%80%E3%83%AD%E3%82%B4)から取得しています。

### データ放送用フォントについて
ワンセグの規格により、データ放送の表示には専用のフォントを使用しています。フォントファイルは[web-bml](https://github.com/otya128/web-bml)を使用しています。

### 緊急地震速報などの受信について
受信した場合は受信の詳細パネルからデータの変化は確認できる（はず）ですが、画面上に警告表示として表示する機能はありません。また緊急地震速報発生時の信号サンプルが入手できないのでテストできていません。

### 受信時の問題について
**頻繁に信号の強度にかかわらず放送の同期が途切れて受信できなくなる現象が確認されます**。おそらく処理速度などが原因と思われますが、根本的な原因はまだわかっていません。

### 外部ライセンスについて
外部ライブラリ・フォント・局ロゴには、それぞれの権利・利用条件が適用されます。
ビルド時に取得・生成されるライセンスと著作権表示は、`web/licenses/`、`web/fonts/`、`web/logos/` を参照してください。
